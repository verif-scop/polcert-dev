# CC 2027 Supplement Packaging

`bin/prepare_cc27.py` builds the anonymous supplementary archive for the
CC 2027 submission and runs its final gate. Nothing in this directory is
copied verbatim into the archive except `template/` and
`recovered/environment/run-paper-bugs.py`.

## Layout

| Path | Role |
| --- | --- |
| `template/` | Files shipped in the archive: top-level README, `environment/` (Dockerfile, test entry points, replay inputs for the added bugs), `evaluation/` README and `TABLE2.md`, and `bugs/catalog.json` (the bug study's rows and PolCert outcomes). |
| `recovered/` | Files recovered from the 2026-09-07 reviewed supplement, which existed only inside that archive: the original `environment/` scripts, `README.md`, `dockerignore`, and the Tables 1–2 generator and packager (`evaluation/bin/run_paper_evaluation.py`, `package_paper_evaluation.py`). |
| `bin/prepare_cc27.py` | Builder and gate. |

## Configuration

All identities live in a JSON file outside this public repository. Keys:

- `polcert_repo`, `polcert_commit`: the frozen PolCert source. Formal `.v`
  files are shipped byte-identical; the gate compares every one of them with
  the commit.
- `pluto_repo`, `pluto_fixed`, `pluto_historical`: the Pluto checkout with
  initialized submodules, and the two snapshot commits. Each snapshot is
  composed recursively from the superproject and its submodules at their
  recorded commits.
- `freeze_dir`, `freeze_scripts`: the freeze results (Table 1 rerun, ISS
  collection, build and test logs, timing) and the scripts copied with them.
- `reviewed_supplement_dir`: the extracted reviewed supplement. Its
  `evaluation/results` and evidence archives become `evaluation/recorded/`.
- `bug_reports`: the upstream bug reports from which `bugs/` is generated (the
  tracker line and Fix sections are dropped).
- `proof_html`: `doc/proof-html` generated by `make proof-documentation` on a
  built tree of the frozen commit.
- `denylist` (regular expressions), `rewrites` (literal replacements),
  `identity_emails` and `hash_repos`. A hexadecimal token is treated as
  identifying when it resolves to a commit in one of `hash_repos` authored or
  committed with one of `identity_emails`. Such tokens are replaced by
  `snapshot` in non-formal text files and fail the gate anywhere else.

## Running

```sh
python3 bin/prepare_cc27.py --config <config.json> --output <zip> [--keep-stage <dir>]
python3 bin/prepare_cc27.py --config <config.json> --output <zip> --gate-only
```

The gate writes `<zip-stem>.gate.json` and exits non-zero unless all checks
pass:

- ZIP CRCs;
- path lengths and no symlinks;
- formal sources byte-identical and complete;
- every JSON file parses;
- every relative link outside `source/` resolves;
- no ELF file, including inside `.tar.xz`, `.tar.gz` and `.zip` members;
- no denylist match and no identifying commit, including in archive members
  and member names;
- no PDF.

The recorded evidence archives are sanitized member by member. Changed members
are marked `anonymized` in `evaluation/recorded/archive-index.json` with their
new hash; `original_sha256` is kept.

After a build, extract the ZIP into a fresh directory, build the image from
it, and run the default and `bugs` modes on a large machine.
