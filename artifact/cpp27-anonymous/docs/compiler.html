Compiler

PolCert represents a bounded loop as statement instances, checks proposed transformations over those instances, and reconstructs a target loop.

The Polyhedral Model

PolCert represents each execution of a loop statement by its loop indices. For example, one execution of A[i][j] = B[i][j] + 1 is identified by the integer point (i,j). Affine inequalities describe which points execute, affine access functions describe which array cells they read and write, and a schedule assigns coordinates that order the points.

Loop optimization changes the schedule or introduces new coordinates. It must preserve every original statement instance and respect any memory dependence that constrains execution order.

Every optional stage has a correctness theorem that connects its output to its input. If a required check fails, the compiler emits no optimized program. When an option is explicitly best-effort, its failed check may retain the last accepted program.

Running Example

The pointwise example begins with a two-dimensional iteration domain 0 <= i0 < N, 0 <= i1 < M. In the output, i0 and i1 enumerate tiles, while i2 and i3 enumerate points inside each tile. Integer division maps every source point to exactly one tile, and the bounded point loops recover the original index values.

Typed Input Program

context(N, M);

for i0 in range(0, N) {
  for i1 in range(0, M) {
    A[i0][i1] = B[i0][i1] + 1;
  }
}

Accepted Verified Program

context(N, M);

if ((1 <= N && 1 <= M)) {
  for i0 in range(0, ((N + 31) / 32)) {
    for i1 in range(0, ((M + 31) / 32)) {
      for i2 in range(max(0, (32 * i0)), min(N, ((32 * i0) + 32))) {
        parallel for i3 in range(max(0, (32 * i1)), min(M, ((32 * i1) + 32))) {
          A[i2][i3] = B[i2][i3] + 1;
        }
      }
    }
  }
}

The parallel check establishes that different i3 iterations do not conflict. The complete case page shows the exact generated bounds and its three matching executions.

Supported Transformations

Loop transformation Change in the model Checked condition
Affine scheduling, including fusion and fission Replace ordering coordinates. No dependence is reversed.
Index-set splitting (ISS) Replace one statement domain with disjoint parts. The parts cover the original domain exactly.
Ordinary tiling Add tile and point coordinates. The coordinate mapping is complete and the selected band is permutable.
Two-level tiling Add two nested groups of tile coordinates. Both levels preserve instances and have a safe order.
Diamond tiling Use coupled tile coordinates for wavefront-shaped tiles. The same instance mapping and band-order obligations hold.
Parallelization Allow iterations of selected generated loops to interleave. Cross-iteration statement instances may exchange order.
Innermost concurrency Apply parallel semantics only to an innermost loop. The parallel check succeeds and the selected loop is innermost.
Constant and block unrolling Expand or group loop iterations. The expanded ranges cover the original range exactly.
Unroll-and-jam Fuse corresponding inner loops after block unrolling. The fused bodies may safely exchange order.

Reusable Instruction Interface

The validators reason about loop instances and memory effects through the INSTR interface. They do not require instructions to be empty or tied to one frontend. The text .loop examples use a lightweight instruction model. Six additional examples instantiate typed scalar and array operations in CTypedLoopSamples.v.
