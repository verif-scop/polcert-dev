Compiler Design

PolCert accepts a structured loop program and a pipeline configuration. External optimization code may propose schedules, partitions, tile layouts, or parallel dimensions. PolCert checks each proposal before it crosses the corresponding semantic boundary. Strict routes reject a failed required check. Some explicitly designed routes instead use a proved fallback, such as retaining the unsplit program when optional ISS cannot be certified, or filtering an uncertified dimension from a multi-dimension request.

What Each Stage Establishes

StageProposal or computationVerified result
Extraction Construct a symbolic polyhedral program whose domain points denote dynamic statement occurrences. Executions of its domain instances reconstruct the source execution.
ISS Split a statement domain into child statements. The children form a disjoint, covering partition and map back to the parent.
Affine scheduling Assign a new affine timestamp to each fixed instance. Every reversed source order is permitted by the access-conflict semantics.
Tiling Introduce tile and intra-tile coordinates in several recognized layouts. Each old instance has one corresponding tiled instance and the tile order is legal.
Loop generation Reconstruct structured loops from scheduled polyhedral instances. The generated loop semantics implements the checked instance semantics.
Parallel annotation Mark one or more generated dimensions as parallel. Every allowed target interleaving can be serialized to an equivalent source order.
Tiling and affine scheduling are different checks. Affine validation checks a new timestamp on the same instance set. Tiling first proves an exact source-to-tiled instance correspondence, then checks the legal order of the introduced tile dimensions. The direct tiling route checks a semantic analogue of a permutable band; it does not call the complete affine-schedule validator as a shortcut.

Correctness Contract

The main result is a target-to-source refinement statement. Compilation may reject. If it returns a target and that target executes, the proof reconstructs a source execution from the same initial state whose final state is related by the instruction semantics' State.eq. In the concrete instruction instance, this relation is pointwise equality on every modeled memory cell.

compile cfg source = Okk target

ParallelLoop.semantics target st st_target

implies

exists st_source, Loop.semantics source st st_source

and State.eq st_target st_source

This is refinement, not partial correctness. The theorem quantifies over every behavior admitted by the target semantics. For a ParMode loop, that target semantics permits arbitrary order-preserving interleavings of the iteration traces. Dependence freedom is established by the checked compiler route, not assumed by the ParallelLoop syntax or semantics.

Component Proofs

Verified Extraction

Question
Does the extracted polyhedral program enumerate the same dynamic statement occurrences as the bounded source loop?
Representation
Each occurrence carries a statement identifier, iterator point, parameter context, instruction, and schedule.
Proof idea
The proof follows the recursive loop structure. Prefix slices identify the occurrences contributed by one iteration; sorted partitions assemble them in source order. A mutual reconstruction argument maps every extracted trace segment back to the source statement or loop that produced it.
Main theorem
ExtractorCorrect.extractor_correct
Source
ExtractorFrontend.v, ExtractorFacts.v, ExtractorCorrect.v

Index-Set Splitting

Question
Do the split child domains represent exactly the original parent instances?
Validator
Checks child shape, parent linkage, coverage, and pairwise disjointness for the proposed cut.
Proof idea
Coverage gives a child for every parent point; disjointness gives uniqueness. The child-to-parent map preserves the instruction and schedule data needed by semantics. Flattening the child traces therefore reconstructs the parent trace without adding, dropping, or duplicating an occurrence.
Main theorem
checked_iss_complete_cut_shape_validate_semantics_correct
Source
ISSRefinement.v, ISSCutSemantics.v, ISSValidatorCorrect.v

Affine Scheduling

Question
May the fixed set of statement instances be sorted by the proposed affine timestamps?
Validator
Searches for a source-ordered pair that the new schedule reverses while the access summaries forbid commuting that pair.
Proof idea
When the polyhedral emptiness checks exclude every illegal pair, any inversion introduced by sorting is a permitted swap. Pairwise commutativity lifts to a permutation of the complete instance list, and stable sorting preserves its semantics.
Main theorem
AffineValidator.validate_correct
Source
AffineValidator.v

Tiling and Permutable Bands

Question
Does the tiled program realize the original work exactly once, and is the new tile order legal?
Validators
The tiling relation checks the quotient/remainder coordinate equations. The direct band checker excludes a conflicting source-ordered pair that decreases in a checked band component under the same prefix.
Proof idea
Euclidean quotient and remainder provide the forward tiled coordinate and its inverse. This establishes occurrence correspondence independently of order. The band proof then reduces every newly reversed pair to the checked semantic component condition. Layout bridges instantiate the argument for ordinary, second-level, scalar-aware, phase-aligned, and diamond layouts.
Main theorems
tiling_retiled_old_to_before_instance_correct_source; semantic_componentwise_permutable_implies_reordering_safe; checked_tiling_sourceb_complete_direct_band_check_correct
Source
TilingWitness.v, TilingRelation.v, TilingBandScheduleValidator.v, TilingBandDirectRuntime.v

Parallel Annotation and Code Generation

Question
Can every trace allowed by a generated parallel loop be explained by the checked sequential source?
Validator
Checks one or more canonical padded schedule coordinates and returns the eligibility facts consumed by code generation.
Proof idea
The target semantics itself allows arbitrary order-preserving interleavings; it does not contain a hidden safety filter. Codegen-origin lemmas map each generated event back to its polyhedral instance. The eligibility certificate proves that cross-iteration events may commute, yielding an ordered semantic companion for the actual target trace. Serializing that companion reduces the result to the verified sequential codegen theorem.
Main theorems
annotated_codegen_many_raw_semantics_ordered; checked_annotated_codegen_many_correct_general_certified
Source
ParallelLoop.v, ParallelValidator.v, RawCodegenOrigin.v, ParallelCodegenCorrect.v

Vector annotation reuses the eligibility argument with an additional innermost-loop check. Its formal target trace remains sequential; the theorem does not claim SIMD instruction generation.

Constant Unrolling and Unroll-and-Jam

Question
Do local loop rewrites preserve the trace before or after the verified polyhedral route?
Transformations
Constant unrolling expands a statically bounded sequential loop. Block unrolling groups iterations; the jam bridge validates when adjacent unrolled bodies may be fused.
Proof idea
Arithmetic lemmas show that the main blocks and peeled remainder enumerate the original iteration interval exactly. Statement insertion preserves expression evaluation under the extended loop environment. The checked jam postpass supplies the local commutativity condition needed to reorder the grouped bodies.
Main theorems
LoopUnroll.const_unroll_correct; LoopUnroll.block_unroll_correct; VerifiedLoopPostpass.apply_checked_unrolljam_correct
Source
LoopUnroll.v, LoopJamBridge.v, VerifiedLoopPostpass.v

Scope and Boundaries

The verified result covers accepted structured-loop compilation routes through the generated ParallelLoop semantics. The following boundaries should be kept separate from that claim:

  • The optimizer's search algorithm is not verified; its proposals are checked.
  • Text parsing and pretty-printing are outside the semantic theorem.
  • The external C compiler and machine runtime are not part of the Rocq model.
  • Vector annotation does not establish SIMD instruction generation.
  • Storage-changing transformations and transformations that change the dynamic occurrence/work multiset are not supported.
  • Rejection is permitted: the validators are proved sound, not complete for every legal optimization.

Generated proof pages are under docs/proof/. The source snapshot and frozen validation data are available through the links in each component and claim row.
