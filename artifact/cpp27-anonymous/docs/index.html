PolCert Supplementary Artifact

This artifact presents PolCert, an end-to-end verified polyhedral compiler. Given a bounded affine loop nest and transformation proposals from an external optimizer, PolCert produces an optimized sequential or parallel loop only after all required checks succeed.

The main theorem states that every terminating execution of an accepted target loop has a source execution from the same initial state with an observationally equivalent result. The verified boundary runs from structured source Loop IR to structured target Loop IR. This archive contains the compiler source, Rocq proofs, generated proof documentation, tests, and evaluation scripts.

1. Compiler Infrastructure and Polyhedral Compilation

The polopt executable parses a structured loop, invokes Pluto to obtain optimization proposals, and dispatches to an extracted verified route. PolCert then extracts the source loop, materializes implied domain guards, and applies the selected index-set splitting, affine scheduling, tiling, post-tiling scheduling, and parallelization stages. It normalizes transformed coordinates, prepares loop generation, generates and cleans a sequential or parallel loop, and applies an optional unrolling or unroll-and-jam postpass.

Verified passes implement extraction, domain strengthening, coordinate normalization, loop generation, cleanup, and unrolling. Validators check affine schedules, exact ISS partitions, tiling instance maps and band order, parallel dimensions, and the exchanges introduced by jamming. The compiler page lists every stage and links it to the corresponding source and proof files.

2. Proofs

Each verified pass or validator establishes a local refinement result. The end-to-end proof composes these results from loop extraction, through the accepted polyhedral transformations, to sequential or parallel loop generation. The proof guide states the main theorem, explains this composition, and links each component to its principal lemmas and Rocq source files.

3. Tests and Scripts

The end-to-end tests pass Pluto transformation proposals through the extracted compiler and display the source and accepted target loops. They exercise affine scheduling, fusion and fission, ISS, tiling, parallelization, and generated-loop postpasses. Pluto remains responsible for optimization search; PolCert checks the resulting transformations without replacing that search with a restricted verified optimizer.

The execution tests compile and run source and optimized programs with identical inputs, compare their results, and record performance. The rejection tests present invalid transformation proposals and the reason each proposal fails validation. Focused Pluto cases show that these checks detect optimizer miscompilations, so the validators can also serve as a correctness oracle for other polyhedral optimizers.
